# BillQyro — Security Architecture Map
> VERIFIED from: `src/services/securityEngine.js`, `src/services/authEngine.js`, `src/services/auditEngine.js`, `firestore.rules`, `src/utils/adminAccess.js`

---

## Authentication Boundary

```
Firebase Authentication
         │
         ▼
App.jsx: onAuthStateChanged()
         │
         ├── user === null → Login.jsx
         ├── user.emailVerified === false → verification gate
         └── user valid → load workspace → Dashboard
```

**Auth Provider:** Firebase Authentication (email/password)  
**Auth State:** Managed in App.jsx via `onAuthStateChanged`  
**Session:** Firebase manages token refresh automatically

---

## Admin Access Boundary

```
Admin PIN Login (AdminPINLogin.jsx)
         │
         ▼
adminEngine.js → validates PIN
         │
         ├── PIN stored: Firestore adminData (NEVER in client code)
         └── Session: adminEngine manages admin session flag
                  │
                  ▼
         AdminLayout.jsx renders admin UI
```

**Admin bypass:** `src/utils/adminAccess.js` — utility for checking admin access  
**Admin PIN:** NOT stored in source code. Stored in Firestore admin collection.

## Audit Engine (auditEngine.js)

Audit events are logged via `logAudit()` (imported in `invoiceEngine.js`):
- Stores to IndexedDB `auditLogs` store
- Synced to Firestore `auditLogs` collection
- Triggered on: payment recording, invoice modification, settings changes

## Firestore Security Rules

File: `firestore.rules` (12.3 KB — VERIFIED to exist)

Key security boundaries (from rule file):
- Users can only access their own workspace data
- `publicInvoices` collection: **read access is PUBLIC** (no auth required)
- Admin collections: restricted to platform admin UID
- `subscriptionPlans`: read-only for users, write-only for admin

> [!CAUTION]
> `publicInvoices` is intentionally public-readable. This is required for the customer portal to work without login. Ensure invoice tokens are cryptographically secure (they are — generated by `dbEngine.generateSecureToken()`).

## Demo Mode Security

When `billqyro_demo_session_active === 'true'` in localStorage:
- All IndexedDB writes are silently blocked
- Demo data is served from memory (demoDataManager.js)
- No real user data is modified

> [!NOTE]
> Demo mode is client-side only. Server-side Firestore operations may still fire if demo session check is not present in all paths.

---

## Data Isolation

All user data is scoped by:
1. `userId` (Firebase Auth UID) — primary isolation
2. `workspaceId` — secondary isolation for multi-workspace

IndexedDB indexes: every store has `userId` and `workspaceId` indexes (verified from `localDb.js`).
